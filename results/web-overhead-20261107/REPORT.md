# Web 承载与填充开销：2026-11-07 本地实测

在同一冻结二进制上完成了 12 个正式用例，每个用例约 12 秒。`web_padding:127` 相比相同承载的 `0`，双向承载字节 / 已验证接收应用字节增加 **10.02%–10.35%（H2）**、**10.02%–10.11%（H3）**。全部受控交互业务交付成功；本实验提供成本与功能证据，没有测量弱网、实际俄罗斯网络或抗识别收益。

正式结果索引为 [formal-01/manifest.json](formal-01/manifest.json)，逐用例统计见 [comparison.json](formal-01/comparison.json) 和 [comparison.csv](formal-01/comparison.csv)。各 trial 子目录保留脱敏的原始业务事件、摘要、relay 生命周期/计数事件、RSS 原始采样及命令。原始私有日志、配置、证书、冻结二进制与源快照保留在 `.local/webbench/formal-01/`。

运行环境为 Darwin 25.5.0 / arm64，18 个逻辑 CPU，Python 3.9.6；PROTO-X 与 pxbench 的嵌入构建信息均为 Go 1.27.1。仅使用 loopback；未施加带宽瓶颈、丢包、额外 RTT 或 CPU/内存隔离。正式启动 2026-11-07T03:57:30.076114+00:00，全部结束 2026-11-07T04:00:02.408808+00:00；业务实际时长累计 144.010873 秒。

候选包含首记录随已完成 TLS 握手后的 HTTP 请求 body 发送的实现；本研究使用该候选测成本，未另外隔离流水发送本身的收益。源快照记录的是冻结时仓库状态，不能单凭它证明外部提供二进制由完全相同的快照构建。

每轮 fresh origin/server/client/relay；第一轮 `h2-p0, h3-p127, h2-p127, h3-p0, tls, quic`，第二轮反向。每例只有一个承载监听与一个客户端端点。旧 `tls/quic` 通过同二进制的 `init --legacy` 生成。Web 使用显式开发证书 pin，未启用 ECH。服务端/客户端发送调度预算 8/2 Mbps，窗口 65536 字节、最多 32 流、priority 开启、adaptive 关闭；Web 调度器按记录大小和填充上界计费。这些预算不等同于全部外层线速。

业务实际经过显式 SOCKS：每秒 5 次 POST、小响应 1024 字节、持久 64 字节 echo（最小起始间隔 100ms）、源端 50ms 节奏 SSE，以及一个源端按 2 Mbps 发送的持续下载。HTTP keepalive 开启，HTTP 并发上限 32；该负载通常使用约四条业务连接，并非同时压满 32 条流。没有后台上传。源速率是每 worker 的应用预算，实际下载 goodput 为 1.829–1.853 Mbps，不能将与 2 Mbps 的差值全归因于协议。
