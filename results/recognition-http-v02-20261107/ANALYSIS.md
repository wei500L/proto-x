# HTTP 承载独立观测：2026-11-07

这组实验完成了真实 H2/H3 代理流、普通 HTTPS 回落、无 ALPN 的 HTTP/1.1、OpenSSL 访客和 ECH 开关的本机核验。**已验证声明的行为，尚未建立一般抗识别能力、俄罗斯现场可达性或相对 VLESS/Hysteria2 的隐蔽性优势。**

所有网络流量发生在授权的本机回环夹具中。原始观察来自用户态 TCP/UDP relay；这不是主机 pcap。TCP 只保留有序字节，不能据此讨论 TCP 分段、重传、网卡时序或真实路径 RTT。QUIC Initial 使用公开 Initial 密钥验证 AEAD 并重组 CRYPTO；后续加密流量及 ECH 内层不在解析范围内。

### 真实代理与 ECH

数据：`results/recognition-native-final2-full-20261107/native-summary.json` 及对应 `*-workload.json`、`*-clienthello.json`、`*-tlscheck.json`。

| 原生承载 | ECH 配置 | 成功代理请求 | 收到的 SSE 事件 | 原生 ClientHello 提供的 ALPN | 可见 SNI 类别 | 独立 TLS 状态 ECHAccepted |
|---|---|---:|---:|---|---|---|
| H2 | 关闭 | 4/4 | 16/16 | `h2`, `http/1.1` | 内层名称类别 | false |
| H2 | 开启 | 4/4 | 16/16 | `h2`, `http/1.1` | 外层名称类别 | true |
| H3 | 关闭 | 4/4 | 16/16 | `h3` | 内层名称类别 | false |

每组是 3 个 32 KiB 受控 HTTP 响应和 1 个包含 16 个事件的 SSE 响应，全部经真实 SOCKS5 客户端、代理服务器和受控目标。响应体逐字节比较；目标服务也记录了全部请求和事件产生时间。每组 12 项检查均通过。四条原生外层连接的 ClientHello 全部解码，无旧自定义 ALPN、抓取截断或 Initial AEAD 解析错误。

ECH 证据分成两部分：原生 relay 记录可见 ClientHello 和成功代理业务；**另一个直连 TLS 诊断连接**记录实际 `ECHAccepted`、ALPN 和证书链验证。诊断连接没有混入原生抓取，也不冒充原生客户端内部回调。原生客户端配置的 ECH 由 `WebClientTLS` 强制接受；对原生接受状态的解释依赖这条失败即终止的客户端策略，不仅仅依赖 ECH 扩展出现。

该独立夹具生成自己的本地 CA，以及同时覆盖内层/外层名称的证书；客户端始终使用 CA/名称验证并加上 pin，没有使用实验 pin-only 模式。**这不表示取得或解决了公网 CA 身份。** 四个顺序客户端可能在恢复保留期中驻留，因此此夹具服务端允许 8 个会话；这里没有据此评估小 VPS 的资源容量。

### 普通站点与主动访客

最终短复核分别使用两个参照：

- `results/recognition-pair-final2-same-20261107/`：同证书、同站点、匹配候选 TLS 辅助函数和 HTTP 窗口的对照，直接调用 `cover.Site`，没有 `Gate` 或 `WebHub`。
- `results/recognition-pair-final2-stock-20261107/`：同证书、同站点，直接使用标准 `crypto/tls` 和 `net/http` 的默认 HTTP/2 配置，以及 quic-go 默认 QUIC 配置，不调用候选 TLS 验证函数。它仍保留本实验的 TLS 1.3 最低版本、超时和监听限制，**不是所有参数均为默认的任意普通网站**。

| 每组参照中的探针 | 候选有效 HTTP 响应 | 对照有效 HTTP 响应 | 声明字段比较 |
|---|---:|---:|---|
| H2 普通/负认证请求 | 11/11 | 11/11 | 全部相同 |
| H3 普通/负认证请求 | 11/11 | 11/11 | 全部相同 |
| Go HTTP/1.1：无 ALPN/显式 ALPN | 8/8 | 8/8 | 全部相同 |
| OpenSSL HTTP/1.1：无 ALPN/显式 ALPN | 4/4 | 4/4 | 全部相同 |

每个参照还有 H2/H3 各两个旧入口探针：旧自定义 ALPN 握手被拒绝，标准 ALPN 下的旧裸记录得到连接/流终止。这四个故意无效的请求不计入上表有效 HTTP 响应分母。最终每组共有 38 个 case，两边都得到 34 个有效 HTTP 响应和四个旧入口拒绝结果；38 对声明字段均相同。

两个参照分别采集候选和普通站点各 38 个 ClientHello，合计 152 个，均解析成功、无截断/解析错误。没有 ALPN 的请求在实际 ClientHello 中也确认未提供 ALPN。主动抓取包含有意提供 `proto-x/1` 的旧入口探针；不能把这些连接说成新原生客户端的指纹。

OpenSSL 是本机已安装的独立 TLS 实现，记录版本为 OpenSSL 3.6.3。它使用 CA/期望名称验证及 `verify_return_error`，不套用 Go 探针的额外 pin。公开报告保留其实际证书验证结果、退出码和 HTTP 响应；原始诊断输出留在私有目录。

“相同”仅指工具声明的状态、协议、选择的通用头、响应体散列和错误类型。Date 不比较，其他私有头值隐藏。时间样本全部保留，但没有证明时序不可区分；更没有把这些 case 的匹配数当作分类器准确率。

## 已发现并保留的问题

1. **无 ALPN 访客兼容性缺陷，已修复并复测。** 旧候选二进制 `6922d08252d901422568711bd525c3800611706ac7f23fe2b35e34cbd9a43e7e` 下，12/12 无 ALPN HTTP/1.1 请求失败，标准 Go 对照 12/12 成功；显式 HTTP/1.1 两边 12/12 成功。原始数据在 `recognition-pair-prepatch-20261107-01`。修复后的 `1e62548af9223635cbdfa68b5bdb404d8dfc6a5e5d74489247bcc9b2b306fb73` 版本在两个参照各 24/24 Go visitor case 完成；最终 cff89b2 版本又完成上表短复核。
2. **旧裸记录的响应存在一次差异，未删除。** 修复前、标准 Go 参照的一个 H2 旧裸记录 case 收到 45 字节后关闭，候选该次为零字节；另外两轮均为零字节。可能与 SETTINGS 发送和非法 preface 关闭的竞争有关，这里没有证实可稳定分类，也没有忽略差异来宣称所有主动行为相同。
3. **首轮普通夹具出现一次 H3 超时。** `recognition-smoke-20261107-01` 的一条 UDP 流将服务端 Initial 原样反映到客户端方向，造成超时和 10 次正确拒绝的客户端密钥 AEAD 解密。relay 改为显式 UDP bind 后，`-02/-03` 未复现；第三轮检查了 52 个互异 backend 端口和零回流。确切操作系统原因仍是疑似归因，不算候选协议失败，也不从历史中删掉。
4. **OpenSSL 初版命令只完成握手而没有发送 HTTP。** `recognition-pair-final-same/stock-20261107` 中双方各 12 次 OpenSSL `request_failed` 均保留；匹配的失败不被算作成功。将 `-no-interactive` 改成 `-nocommands` 后，`recognition-openssl-command-check-20261107` 的 4/4 试运行成功，最终版本两个参照也各 4/4 成功。
5. **原生首轮达到抓取前缀上限。** `recognition-native-final2-20261107` 的全部 16 个代理请求成功，但两个 H3 场景超过默认每方向 128 个数据报的留存上限，报告明确标记截断。将原生夹具有界预算改为 1 MiB/512 个数据报后，`recognition-native-final2-full-20261107` 四组全部完成无截断记录。原始上限轮仍保留。

这些历史目录绑定各自二进制、配置和工具行为。不能把后续工具修复后的结果倒填到早期样本，也不能把旧 v0.1 网络性能数据推广成新 H2/H3 承载已经胜过基线。

## 当前结论边界

新原生流量确实通过标准 H2/H3 HTTP 承载提供代理业务；声明的普通访客和负认证请求回到普通站点；已验证 ECH 开关的实际行为及可见名称类别变化。相对早期原型，旧自定义 ALPN 这条识别线索没有出现在这四条新原生连接中。

仍然可见 TLS/QUIC 实现、扩展/参数、包长、HTTP 用法和时序等线索。这里没有多应用、多站点 cover 数据集，没有按会话/主机分离的训练与测试，没有 TPR/FPR、主动探测大样本、公网抓包、真实 DPI 或俄罗斯现场数据。低速率、填充和真实 HTTP 语义的更广泛收益需要另行测量。

工具有 11 个已执行通过的 Python 检查（公开 RFC 9001/RFC 9369 向量、损坏/截断/重组、比较器失败与缺失样本）以及 Go 构建/vet 检查。它们验证测试器的若干关键属性，不构成协议安全证明。
