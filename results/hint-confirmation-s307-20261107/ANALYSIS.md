# 稀疏副本独立验证：seed307，固定3×90秒

预声明的方向性主判据通过：相对同一程序关闭副本，开启副本后的HTTP完整响应p95下降18.3%、echo p95下降21.6%；没有增加请求失败或完整超时。代价是双向外层字节增加11.4%、下载goodput下降1.2%。这是一项保留单独种子的复制验证，不是统计显著性检验或全面优于Hysteria的证明。

与正式Hysteria2相比，开启副本后的echo p95较低16.4%，HTTP p95仅低1.5%；HTTP/echo p50反而分别高38.3%/28.7%，SSE p99高6.5%、SSE最大间隙高25.7%，双向外层字节多24.4%。Hysteria没有>250ms完整SSE间隙，PX on有一次。中位数、流式尾部与字节成本必须和局部p95收益一起判断，不能只选有利指标。

研究者在全部15项筛选完成后释放此前未使用的seed307，首先写入PREDECLARED.json，再运行一次随机顺序off→on→Hy Brutal6。相同hint二进制、参数和受控源站，每项固定90秒测量加3秒预热；90秒是运行前确定的延长时长，筛选的25秒结果没有并入本表。没有调参、换seed、补跑或删样本。decision.json核对预声明未改动、启动时间在声明之后、全部实测至少90秒、实际顺序/参数/程序/源码/配置均匹配；三个试验均完成。

链路为本地Debian13 arm64 VM内真实Linux TCP/UDP栈与包级netem：双向各5%独立随机丢包、各5ms抖动、名义RTT60ms、物理下8/上2Mbps、额外名义队列100ms。两个方向使用307/308种子；同seed不保证每个应用消息受到相同损伤。每组一个源端1Mbps后台下载、HTTPS POST5/s（自有CA验证、keep-alive、响应1024字节）、echo最小间隔100ms、SSE源端50ms、完整超时3秒，每进程GOMAXPROCS=1。源端1Mbps是应用下载预算，不是总加密外层预算。

PX off/on均为同一个实验可执行文件，默认Reno、双端64KiB窗口、priority=true、adaptive=false、应用pacer下8/上2Mbps，完整配置只差双方sparse_redundancy布尔值。副本有8ms提交延迟、40ms提交前年龄限制、额外10%速率/64KiB每秒上限，同时消耗总应用pacer；QUIC内部队列没有硬到期保证。Hy为正式2.13.0，Brutal下6/上1.5Mbps、丢包补偿开启。这里不比较0.1.1、CC fork或其他新二进制。
