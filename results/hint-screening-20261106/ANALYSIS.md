# 稀疏副本筛选：同程序开关消融与正式Hysteria2

稀疏副本对echo尾延迟呈现较一致的收益，但HTTP与SSE依赖负载条件。共同源限速2.5Mbps时两个种子的HTTP、echo及SSE p99均改善；1%丢包且后台不限速时HTTP p95/p99反而变差，SSE结果方向不一致。本轮没有证明其全面优于正式Hysteria2。

这是本地Linux VM包级netem的15项探索性短测，不是俄罗斯现场测试。每项25秒测量另加3秒预热，HTTP每秒5个POST、echo最小间隔100ms、SSE源端50ms、一个后台下载、3秒完整超时，每进程GOMAXPROCS=1。物理链路8/2Mbps、名义RTT60ms、双向各5ms抖动、额外名义队列100ms；表中1%/5%均为每方向独立丢包概率。顺序用各自seed打乱，同seed不意味着同一应用消息逐个遇到相同损伤。

PX off/on使用同一个冻结实验程序、默认Reno、双端64KiB信用窗口、priority=true、adaptive=false、应用pacer下行8/上行2Mbps；双方配置只差sparse_redundancy布尔值。接收方即使不发送副本仍接受副本，所以控制组双方都明确关闭。Hy为正式2.13.0，Brutal下行6/上行1.5Mbps及丢包补偿；所有组面对相同物理链路及相同每worker源端限速，源限速不是总外层流量预算。

机制仅复制符合现有高优先级判定的DATA，约8ms后向QUIC datagram队列提交，提交前年龄上限40ms；副本同时消耗原来的总应用pacer和一个额外的10%速率预算（最多64KiB/s）。QUIC内部排队可能继续延迟副本，40ms不是线上到期保证；原始可靠数据流依然存在，接收端按偏移去重。此实验不判断副本是否与原始帧落在不同网络包中。

共同源2.5Mbps时，on相对off的HTTP p95下降7.4%/26.0%，SSE p99下降38.5%/25.8%，下载goodput变化+0.1%/−0.8%；外层字节增加7.4%/5.6%。相对正式Hy，两种子的HTTP及echo p95仍较高，SSE p99也不是稳定占优。

5%丢包、源1Mbps追加场景在执行前写入PREDECLARED-LOSS5.json，采用训练seed317。on相对off的HTTP p95下降28.1%、echo p95下降31.2%，goodput下降0.8%，双向qdisc字节增加11.9%。on在这一个短测中HTTP/echo p95也分别低于Hy约7.0%/23.9%，但HTTP p99高40.3%、SSE p99高15.4%；不能选择其中一部分指标宣称整体胜出。该场景是在观察早期训练结果后追加的探索实验，不能当作独立确认。

qdisc为测量窗前后内核SKB字节差值，合计上下两方向，含交互、控制与重传；它与下载字节的比值不是纯协议头开销，也不是移动网络账单字节。全部快照差值复算一致。CPU为一个核心的平均百分比，RSS按100ms采样；单会话短测资源不能外推长期、多用户上限。

HTTP全部1875/1875成功。Echo3618/3630成功，差额12全部是测量结束截尾；无HTTP/echo应用失败、完整超时或拒绝。SSE共7435个token，序列/源错误及异常结束均为0。唯一完整接收间隙超过250ms发生在seed317的on组：255.152160ms，源间隙50.773796ms、超出源节奏204.378364ms，原始events.jsonl第996行、seq431；源生成延迟0.799905ms。其他组没有>250ms完整间隙，全部组没有>1s间隙或>250ms末尾截尾。各组源间隙p99最多52.155ms、源生成延迟最大9.622ms；SSE时序使用单调时间，不用两端墙上时钟相减。

五个on组均有服务端副本日志，客户端退出日志全部缺失，不能将缺失读作未发送。冻结client退出路径先关闭listener，accept循环可能在Session.Close计数输出前返回；这一竞态保留在该实验程序中，不为补日志而改二进制。off组正常不输出副本计数。sent_datagrams仅为成功提交到QUIC，first_delivered_bytes仅为副本先交付，不能证明原件发生物理丢包；QUIC打包或调度也可能产生收益。计数范围包含启动/预热/测量/关闭，多个无session ID记录不直接求和，不能用来替代测量窗qdisc成本。
